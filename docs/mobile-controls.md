# NULL SECTOR · 移动端操作对标与优化方案

> 对标对象：《和平精英》(PUBG Mobile) / 《使命召唤手游》(CODM) 的移动端操作方案
> 本轮已落地部分见第四节（含实测数据）；第五节为下一轮候选与不做的理由。
> 验收：`verify17-touch.js` 28 条断言全绿（移动端 24 条 + 桌面零影响 4 条）。

## 一、当前实现盘点（改动前实测）

| 环节 | 现状实现 | 代码位置 |
|---|---|---|
| 摇杆 | 左半屏任意位置按下即出现（跟随式），死区 0.14、半径 58px，纯模拟量 | `Input.setMove()` / `#tJoy` |

| 布局 | 固定位置与尺寸（移动端媒体查询里硬编码 64/104px） | `@media (pointer:coarse)` |
| 灵敏度 | 单一档位（`touchSens`） | `Settings` |

## 三、痛点与差距（按严重度）

**P0（不改则移动端体验不成立）**
1. **开火即失瞄**：按住开火键时指针被 `setPointerCapture` 捕获，右半屏的 look 通道收不到任何事件 → 玩家必须"瞄准—松手—开火"交替，无法跟枪与压枪。这也是"手机上手感像半成品"的最主要原因。
2. **零辅助瞄准**：触屏是绝对定位 + 无物理反馈，缺少吸附/减速时，远距离跟枪成功率极低。主流方案都是"默认开启弱吸附"。
3. **自动开火语义错误**：旧 `autoFire` 打开后会**从开局持续开火到本局结束**（与"对准才开火"完全不同），造成走火、弹药浪费、误暴露，玩家实际会把它关掉 → 该设置形同废设。

**P1（明显影响上限）**
4. 无自动奔跑：长距离转移必须一直压着摇杆边缘，效率与舒适度都差（主流标配）。
5. 无触感反馈：移动端"打击感"的一半来自震动（开火/命中/受击），缺失时射击像"打字"。
6. 开火时无独立灵敏度：压枪需要更低灵敏度，追枪需要更高，单档无法兼顾。
7. 布局不可调：小屏机型按钮过大/过小都无解；左手玩家完全无法使用（按钮全在右侧）。
8. 手机媒体查询把按键尺寸**硬编码**，任何"按键大小"类设置都会被静默覆盖（本轮实测踩到）。

**P2（需要新机制，列为下一轮）**
9. 无 ADS 开镜（本作武器无瞄具与倍镜体系）。
10. 无蹲/趴/滑铲/探头（需 `CONFIG.PLAYER.H` 与相机高度、碰撞半径联动改造）。
11. 无陀螺仪（iOS 需权限申请，Android 需 `deviceorientation` 兼容）。
12. 灵敏度未分档、无水平/垂直分离。
13. 布局不能拖拽自定义、无多套方案。

## 四、本轮已落地（含实测数据）

| # | 优化项 | 实现要点 | 实测结果 |
|---|---|---|---|
| 1 | **开火键拖动转视角** | 在 `#tFire` 上监听 `pointermove`，位移并入同一条 look 通道；指针已被捕获，滑出按钮范围也持续生效 | 按住开火拖动 → Δyaw = 0.176；拖动期间持续射击（2 发）；松手立即停火 |
| 2 | **辅助瞄准（三档）** | 用**角度差**判定准星附近的敌人（不用投影矩阵，避免相机矩阵落后一帧）；弱=6° 锥/速率 3.4，强=10°/7.0；只帮"对准"，不改弹道与伤害 | 关闭：4.00° → 4.01°（不收敛）；弱：4.00° → **0.85°**；强：4.00° → **0.19°**；无输入时 Δyaw=0（不抢控） |
| 3 | **对准自动开火** | 新增 `aimFire`：准星压住敌人（≤3.2°）即开火；与旧「自动开火」并存，玩家可分别开关 | 准星对敌 900ms 内自动射 **4 发**；准星移开 30° → **0 发** |
| 4 | **自动奔跑** | 摇杆推满（≥0.82）且前向，持续 0.55s 进入奔跑；回中即退出 | 速度 5.20 → **8.17**（走 5.2 / 跑 8.2）；关闭时保持 5.20 |
| 5 | **开火灵敏度（压枪）** | 按住开火键时 `touchSens × fireSens`，独立设置项 | 200% 档转视角幅度 0.115 → **0.243**（≈2.1×） |
| 6 | **触感反馈** | `navigator.vibrate`；开火 8ms / 命中 14ms / 受击 [22,30,22] / 击杀 26ms；iOS 无 API 时静默跳过；可关 | 击杀+受击触发 2 次、开火触发 1 次；关闭后 **0 次** |
| 7 | **按键大小** | `--tb` CSS 变量，所有触屏按钮尺寸统一乘它（含手机媒体查询，修掉硬编码覆盖） | 104px → **146px**（1.4 倍） |
| 8 | **左手模式** | 按钮组镜像到左侧，**摇杆与视角区域左右互换** | `.lh` 生效；左半屏不再出摇杆、右半屏出现 |
| 9 | 教程同步 | 触屏教程页重写（自动奔跑 / 火键拖动 / 辅助瞄准 / 自动开火 / 震动 / 布局），中英双语 | 双语页面随语言切换 |

**对既有行为的保护**：桌面端零影响（`touchMode()` 为假 → 触屏逻辑整体不启用，合成触屏事件也不驱动视角）；键鼠灵敏度、原有 5 键、多点触控语义均未改动；辅助瞄准**不改变伤害与命中判定**（只影响视角朝向），因此不影响成就"神射手"等精度统计。

## 五、下一轮候选（本次刻意未做）

| 候选 | 为什么暂缓 | 建议做法 |
|---|---|---|
| **ADS 开镜** | 本作武器没有瞄具/倍镜体系，需要新增"开镜状态"：视野收缩、散布收紧、后坐降低、独立灵敏度、开镜动画 —— 是玩法级新机制而非手感调优 | 先给 3 把直射武器加 `adsK=1.35` 视野倍率 + `spreadAds`，再补开镜按钮与灵敏度分档 |
| **蹲 / 趴 / 滑铲** | 需要 `CONFIG.PLAYER.H`、相机高度、碰撞半径、脚步声与后坐多系统联动 | 从"下蹲"单项开始：`H:1.8→1.25` + `EYE:1.7→1.15` + 移速 ×0.55 |
| **探头（Peek）** | 需相机水平偏移 + 掩体判定，收益偏进阶 | 左右各一键，相机沿本地 X 轴偏移 ±0.45m |
| **陀螺仪** | iOS 需用户授权弹窗，误触代价高；本作是 PvE 波次生存，收益低于竞技 FPS | 默认关，设置里开启并"仅开镜时生效" |
| **布局拖拽自定义 / 多套方案** | 需要编辑模式 UI（拖拽手柄、吸附网格、方案存储与切换） | 复用现有 `Settings` 存储，新增 `layouts` 数组 + `#layoutEdit` 覆盖层 |
| **灵敏度分档（水平/垂直）** | 本作无倍镜体系，分档收益有限 | 先做"腰射/开镜"两档，与 ADS 一起上 |
| **开火跟随（hold-to-track）** | 与辅助瞄准功能重叠，易变成"自动瞄准" | 作为辅助瞄准的"强"档增强项而非独立开关 |

## 六、验收与回归

- 新增 `verify17-touch.js`：**28 条**断言（移动端 24 + 桌面零影响 4）
  - A 触屏基础与 7 个新设置项注册
  - B 火键拖动转视角 / 拖动期间持续开火 / 松手停火
  - C 开火灵敏度倍率关系
  - D 辅助瞄准：关闭对照组不收敛、「弱」明显收敛、「强」收敛更快、无输入不抢控
  - E 对准自动开火：对目标开火 / 移开后停火
  - F 自动奔跑：开启进跑速 / 关闭保持走速
  - G 触感：击杀+受击 / 开火 / 关闭后为零
  - H 布局：按键缩放实际生效 / 左手模式摇杆换边
  - I 桌面端：不进入触屏模式、合成触屏事件不影响视角、设置项默认值正确、无报错
- 触发方式：`NODE_PATH=<托管 node_modules> node verify17-touch.js`
- 同时纳入既有 14 套件回归（含三视口零遮挡审计、英文模式零中文扫描）。

## 七、一句话结论

移动端"能不能玩"的门槛在**开火与视角能否同时进行**（P0-1）与**是否有吸附/减速的辅助瞄准**（P0-2）；门槛之上决定"爽不爽"的是**自动奔跑、触感反馈、压枪灵敏度**与**可调布局**。本轮把 P0 三项与 P1 五项全部落地并用实测数据固化，剩余 P2 项（开镜、身法、陀螺仪、布局拖拽）属于新机制，建议按第五节顺序逐项推进。
