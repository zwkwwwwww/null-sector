## 二、新增玩法

### 1. 随机事件 Events（每波随机触发，重玩不枯燥）
第 2 波起，每波开始按 65% 概率触发 1 个事件（持续 20–24s），带全屏横幅 + 专属音效 + 右上角倒计时：

| 事件 | 效果 |
| --- | --- |
| 离子风暴 ION STORM | 护盾停止回充 |
| 弹药荒 DROUGHT | 补给站冷却 ×2 · 掉落概率减半 |
| 敌群狂化 FRENZY | 敌方移速 +30% |
| 双倍积分 DOUBLE | 得分 ×2 |
| 重力异常 LOW-G | 跳跃 +30% · 下落变慢（结束精确还原物理参数） |
| 猎杀令 HUNT | 击杀额外 +50% 得分 |

事件开场还会掉落 1 份增益道具，逼玩家在"顺风"与"逆风"之间调整策略。

### 2. 增益道具 Powerups（5 种，8–14 秒）
狂暴 RAGE（伤害 ×1.5 · 射速 ×1.25）、时缓 SLOW（敌方 40% 移速）、无限弹药 INFUSE、护盾过载 AEGIS（护盾回满且**上限 +25**）、疾行 HASTE（移速 +35%）。
来源：精英必掉 · 普通击杀 6% · 补给站按间隔产出 · 随机事件开场掉落。同类叠加只刷新时长，HUD 左侧实时显示剩余时间条。

### 3. 连杀倍率 Combo（鼓励连续作战）
3 秒窗口内连续击杀累加，倍率 `1 + ⌊连杀数/2⌋ × 0.25`，上限 ×4（精英/重甲额外 +1 连杀）。HUD 顶部显示 `×倍率` 与窗口进度条，5/10/15 连杀触发慢镜与提示音。

### 4. 精英变体 Elite（第 3 波起）
按概率把普通敌人升级为精英：HP ×1.9 · 伤害 ×1.3 · 得分 ×2 · 体型 ×1.25（含碰撞半径）+ 专属光环与紫色飘字标记，击杀**必掉**增益道具。采用 monkey-patch 方式实现，未改动 Enemies 源码。

### 5. 最高分与生涯统计 Best（留存）
- 按难度分别记录 `{score, kills, wave, time, acc}`，主菜单「历史最佳 // BEST SCORE」面板与结束页同步展示，破纪录时金色闪光 + 上行音效。
- 生涯统计：累计局数 / 累计击杀 / 最高连杀 / 累计时长。
- 无尽模式仍保留原有的「抵达波次」历史最佳（未破坏旧存档键）。

### 6. 核心循环补完：软重开 + 暂停菜单
- **软重开 `Flow.restart()`**：不再 `location.reload()`，完整清场（敌人 / 弹丸 / 拾取 / 特效 / 连杀 / 事件）后原地开新局，同难度同地图。
- **返回基地 `Flow.abort()`**：不刷新页面回到菜单，HUD 收起、场上清空。
- 暂停层新增「设置 / 重开本局 / 放弃并返回基地」三个按钮。

### 7. 反馈与手感
击杀投影飘字（普通/重甲/连杀/精英四档分色分号，精英带 ELITE 标，同屏上限 24）· 连杀档位闪烁 · 低血红色脉冲与分级心跳 · 受击红闪与震屏（吃设置里的震动强度）· 连杀与精英击杀慢镜 · 9 个新合成音效（crit / combo1-3 / event / buff / record / elite / lowhp）。

### 8. 移动端与引导
- **触屏控制**：左虚拟摇杆移动 + 右半屏拖拽转视角（多点触控）+ 开火 / 跳跃 / 换弹 / 切枪 / 暂停按钮；触屏模式下自动跳过指针锁定；可选「自动开火」。
- **响应式**：`≤820px` 缩放 HUD、增大点击区、适配安全区；`pointer:coarse` 才显示触控层——**桌面端行为与视觉零变化**。
- **新手引导**：首次进入自动弹出 3 页操作说明（键鼠 / 触屏 / 战斗目标），菜单保留「操作说明 // HOW TO PLAY」入口。
- **进度可视化**：菜单新增成就进度条与各难度最高分面板。

### 9. 设置项扩展（7 项）
画质档（像素比/阴影）· 自动开火 · 触屏灵敏度 · 强制显示触屏控制 · 准星样式（4 种）· 显示 FPS · 事件与增益提示开关。

## 五、集成接线说明（后续开发必读）

`CONFIG` 顶部注释区（约 923–931 行）已写明接入口。集成层提供三个**安全回落**查询函数（`CONFIG.BASE` 之后）：

```js
SH_MAX()          // 护盾上限 = CONFIG.SHIELD.MAX + Powerups.add('shieldMax',0)
PMUL(k, def)      // 增益系数：武器伤害 ×PMUL('dmg',1)、射击间隔 ÷PMUL('fireRate',1)、移速 ×PMUL('moveSpeed',1)
EMOD(k, def)      // 事件系数：Events.mod(k, def)
```

- 武器伤害/射速：`Weapons` 内 `w.dmg*PMUL('dmg',1)`、`fireRate/PMUL('fireRate',1)`（含转管机炮的爬速分支）
- 玩家移速/护盾上限：`Player.update` 与 `HUD` 护盾条
- 敌人移速：`Elite.respeed()` 对 `Enemies.list` 做一次字段修正（不改 Enemies 源码）
- **击杀统一走 `Bus.emit('kill',{pos,type,name,score,elite,heavy})`**：连杀、飘字、慢镜、增益掉落全部订阅该事件，后续要加击杀反馈只需再订阅，不必往击杀点插桩
- 其他新增事件：`event:start`/`event:end` · `powerup:get`/`powerup:end` · `combo:tier`/`combo:end` · `elite:spawn` · `record`

## 七、已知取舍与后续扩展点

**当前取舍**
- 事件不叠加（同一时刻只有 1 个事件），保证每个事件的辨识度；
- 精英的速度加成仅在事件/增益状态变化时刷新，事件中途新刷出的敌人不会立刻吃到加成（`Elite.respeed()` 为一次性字段修正，见下）；
- 移动端 390px 宽下，开局的 WAVE 横幅会短暂压住左上角生命面板（横幅 2.5s 后消失）。

**建议的下一步（按性价比排序）**
1. `Events.update` 内每 0.5s 节流调用一次 `Elite.respeed()`，让事件期间新刷敌人也吃到移速加成；
2. 移动端把 `#miniWrap`（小地图）在 `≤480px` 隐藏，彻底解决 HUD 拥挤；
3. 触屏设备把新手引导默认页设为「触屏操作」；
4. 扩展点：Boss 波（用 `CONFIG.ETYPES` 加精英化 Boss + 专属血条）、武器改装（挂在 `CONFIG.WEAPONS` 附加字段）、每日挑战（固定种子 + 事件序列）、本地排行榜（复用 `Best` 的存档结构）。

# 九、准星修正：T 形（crossStyle=2）

**规格（用户最终确认）**：T 形由**三道杠**组成 —— **两道横杠**在水平方向（一左一右）、**一道竖杠**在准心点正下方；**三道杠都不接触准心点**；交点只留琥珀色中心点用于瞄准。即「十字去掉上竖线」。

**原缺陷**：v3.0 的规则恰好写反 —— 隐藏了这三段、只留下**上竖线**，屏幕上只剩中心上方一根 9px 短竖线（`cross-before-cs2.png`）：

```css
/* 修复前：只剩中心上方一根短竖线 */
#cross.cs2 .cl.b,#cross.cs2 .cl.l,#cross.cs2 .cl.r{opacity:0}
```

**最终实现**（`patches/13-fix.js`，一行规则，几何完全复用十字的基础定义）：

```css
/* v3.1.4 T 形准星：左横 + 右横（一左一右）+ 下竖（准心点正下方），都不接触准心点 */
#cross.cs2 .cl.t{opacity:0}
```

- 三道杠的间距与长度自动跟随设置里的「**准星间距**」（`--sp`）。
- 交点处保留琥珀色中心点，T 形下依然能精确瞄准。

# 十、v3.1.5 修正：第二局起 过热条/预热条/锁定条不可见

> 触发：「在第一次进入以后的每次游戏，转管机炮的过热进度条与锁定导弹的锁定进度条不再可见。」

**根因（v3.1.3 离场清理引入的回归）**：`#spinWrap`（预热）/ `#heatWrap`（过热）/ `#lockWrap`（锁定）的显隐由 **class 驱动**（`#x.on{opacity:1}`），而 v3.1.3 的 `clearCombatHud()` 给它们写入了**内联** `style.opacity='0'` —— 内联样式优先级高于类规则，且之后没有任何代码再清它。于是第二局起 class 照常切到 `on`、条却永远不可见（探针实测：`heatOn:true, 计算opacity:0, 内联:"0"`）。

**修复**（`patches/14-fix.js`）：清理时按驱动方式分两类处理——

| 元素 | 驱动方式 | 清理动作 |
| --- | --- | --- |
| 受伤红闪 / 低血红晕 / 时缓染色 / 伤害来源 / 连杀条 / 事件倒计时 | 内联 opacity（HUD 逐帧重写） | 写 `0` ✓（维持 v3.1.3 行为） |
| 预热 / 过热 / 锁定条 | **class `on`**（CSS 控制） | **移除内联 opacity**（交还 CSS）+ 摘掉状态类 `on/ready/hot/over/locked` |

**验证**：探针两局对比（第一局 `opacity:1` → 结算 → 第二局开火后仍 `opacity:1`，内联无残留）；`verify04-ui-layout.js` 新增 E 节 3 条断言（连续两局过热/预热条可见 + 第二局锁定框可见），全套件 **32 / 32**；既有 7 套件回归全绿。

# 十四、v3.2.1：英文模式彻底去中文

> 触发：「还有中文，全部改英文，英文模式不要出现中文」。

## 14.1 之前的问题

v3.2 的 i18n 只覆盖了 25 组静态选择器 + 部分动态文案。切到英文后仍有 **280+ 处中文**残留（主菜单副标题、HUD 标签、难度与地图名、设置项全部 label/hint、作战简报整篇、敌情档案 5 个敌种的全部特性/反制、武器档案 6 把武器的参数与说明、创意工坊整篇 MOD 格式文档、以及大量运行时提示）。

## 14.2 方案：三层替换引擎

在 `I18N` 模块内新增全文档扫描引擎（`patches/23-i18n-full.json`，标记 `NS32_I18N_SWEEP_V1`）：

| 层 | 机制 | 用途 |
|---|---|---|
| ① HTML 整块 | `HTMLEN`：选择器 → 英文 innerHTML（31 块） | 长文档（作战简报、MOD 格式说明、工坊提示、各面板标题…），译文质量最高 |
| ② 属性 | `ATTREN`：`选择器\|属性` → 英文值 | textarea / input 的 placeholder |
| ③ 文本节点 | `DICT`（307 条）+ `RE`（106 条正则） | 动态生成的档案、运行时提示、带变量的播报 |

替换顺序：**整段精确匹配 → 子串替换（只用 ≥3 字的键）→ 正则 → 全角标点归一**。

两个关键设计：
- **精确匹配优先**：像「中」「十字」这类 1–2 字的设置项选项值只在整段相等时替换，否则会把「十字掩体」误伤成「CROSS掩体」。
- **正则源串必须含中文**：否则会误伤已译好的英文（生成器里自动丢弃不含中文的模式）。

**增量扫描**：`MutationObserver` 只监听变动子树（`characterData` 走父节点、`childList` 走目标子树），rAF 去抖 —— 面板由 JS 动态生成（档案/工坊/成就）也能自动补译，且不会每帧全文档遍历。

**可逆**：首次替换时把原文存进 `ORIGTXT`（文本节点 Map）/ `ORIGHTML` / `ORIGATTR`，切回中文时逐条还原，`document.title` 与 `<html lang>` 同步切换。

## 14.3 覆盖范围（英文模式）

主菜单 · 作战简报（整篇）· 作战配置（难度 5 项名与描述、地图 6 张名与描述）· 系统设置（16 项 label+hint、选项值 低/中/高、准星 4 样式）· 敌情档案（5 敌种：属性标签 + 特性 + 反制）· 武器档案（6 把武器：名称、槽位、全部参数、特性、战术、隐藏武器解锁条件）· 成就档案（框架 + 15 项名称与描述）· 创意工坊（预设、编辑器、整篇 MOD 格式说明、校验提示）· 暂停/结算/DEV 确认/触屏按钮/新手引导 · 对局 HUD 全部标签与状态 · 事件/增益/连杀/播报/结算/toast 等运行时文案 · 中文标点与全角空格归一。

# 十九、v3.4.3 修正：改造显示与实际一致 · 画质回归原水平 · 英文完善

> 触发：「武器升级后界面显示的数值与实际升级结果不一致；同时画质相比之前明显下降；将英语界面继续完善，成就仍然是中文」。

## 19.1 改造：面板显示 ≠ 实际结果（4 个真实缺陷）

| # | 缺陷 | 实测证据 |
|---|---|---|
| 1 | 面板只显示**名义百分比**（每级 +8%/+10%/+6%/+8%），与实际写入的数值不符 | 弹匣 12→13 面板写 `+10%`，实际 `+8.3%`；换弹实际是**减少** 8%，面板却写 `+8%`（符号相反） |
| 2 | **套用时机错误**：`Econ.apply()` 被插在 Weapons 模块体内（IIFE 求值时 `const Econ` 尚在 TDZ，被 try/catch 静默吞掉），而 `startGame` 又在 `Weapons.reset()` **之后**才套用 | `reset()` 按 `w.magSize` 初始化弹匣 → 面板显示 13 发、**开局实际只有 12 发**（首次换弹才纠正） |
| 3 | **武器档案（ARSENAL）是启动时的静态快照**，买完改造不重建 | 面板已显示伤害 21.6，武器档案仍写 20 |
| 4 | **基准漂移**：MOD 装载 / `resetToBase()` / mech 伤害倍率都会重建 `CONFIG.WEAPONS`，而 Econ 仍用开机快照回写 | **会把 MOD 武器的数值覆盖成原版基准值**（MOD 玩家看到"改造把武器打回原形"） |

**修法（从构造上杜绝"显示 ≠ 实际"）**

- **单一真源**：改造数值只在 `statDmg/statMag/statRof/statRel` 四个函数里算一次，`apply()` 写回 CONFIG.WEAPONS 与面板 `preview()` 都用它们。
- **新增预览接口** `Econ.preview(i,k)`：返回 `{cur, next, unit, dec, kind, pct, full}` —— `cur/next` 是与 apply 同源的真实数值，`pct` 由真实数值算出（所以弹匣会如实显示 +8.3%，换弹显示 −8%）。多档武器 / 导弹的伤害是纯倍率，用 `kind:'mult'` 显示 `×1.08`。
- **面板改为显示「当前 → 下一级」**：`伤害 ●●○○ NOW 23.2 → 24.8 +6.9%`，玩家能直接对照。
- **套用提前**：`Econ.apply()` 移到 `Weapons.reset()` **之前**（并修正 `Weapons.reset()` 内部首行的套用，双保险）。
- **基准自愈（指纹）**：`apply()` 每次比对「上次写入的指纹」，不符即以当前值为新基准重新采样 → MOD 数值不再被抹掉，且仍然幂等。
- **档案重建**：武器 / 敌情档案改为**每次打开时重建**，购买改造后也立即重建。
- **数值格式化**：档案里的伤害/换弹/射击间隔统一小数位（不再出现 `1.0120000000000002`）。

## 19.2 画质下降（根因：新增的"性能档位"默认档把阴影关了）

# 二十一、v3.4.5：重置改造改为「返还已投入信用点 + 清空改造」

## 21.1 问题

原实现是：

```js
function reset(){ credits=0; upg={}; save(); apply(); }   // 清空钱包 + 清空全部升级
```

确认文案也照实写着「此操作清空钱包与全部升级」—— 也就是说玩家点一下「重置改造」，**攒下的信用点会被整份没收**。这既不符合直觉（重置改造应当只是"退掉改造"），也不是通行做法（重置/洗点通常全额或按比例返还）。

## 21.2 改动

**语义**：重置改造 = 清空全部改造等级 + 把**已经投进去的信用点全额返还**到钱包；钱包里原有的余额分文不动。

| 位置 | 改动 |
|---|---|
| `Econ.spent(i,k)` | 某条改造线已投入的信用点：**逐级按真实价格累加**（与 `cost()` 同公式、同取整），不是用当前价格反推 |
| `Econ.invested()` | 全部改造已投入总额 = 重置时应返还的数额 |
| `Econ.reset()` | 改为 `credits += invested(); upg={}; save(); apply();` 并**返回返还数额** |
| 钱包条 | 新增「已投入 N」/ `INVESTED: N`，让玩家在点之前就知道能退回多少 |
| 确认框 | 有升级：`确认重置改造？将清空全部改造，并把已投入的 798 信用点全额返还到钱包`<br>无升级：`确认重置改造？当前没有已购买的改造`（不再谎称会清空钱包） |
| Toast | `改造已重置 · 返还 798 信用点` / `MODS RESET · refunded 798 credits`（返还为 0 时保持原文案） |

**关键不变式**：返还数额 == 玩家逐次购买**实际被扣掉的总和**（含 `costMult=1.55` 的逐级递增与 `Math.ceil` 取整）。实测：买 11 次共扣 1790 → `invested()` 1790 → 重置返还 1790。

## 21.3 顺带修掉的一个"看不见"的缺陷

`#toast` 的 `z-index:16`，而所有全屏面板 `.layer`（`#menu` / `#upgScreen` / `#endScreen` …）是 `z-index:40` —— **面板打开时，所有 toast 都被压在面板下面，玩家根本看不到**：重置返还款看不到、购买成功看不到、结算入账也看不到。

已把 `#toast` 提到 `45`（低于 `#fade`=60 与 `#bootMask`=200，转场遮罩仍能盖住它）；`#toast` 本就带 `pointer-events:none`，所以不会挡任何点击。

## 21.4 一次补丁事故与由此建立的两道哨兵（重要）

生成 64 号补丁时，我用「找出第一行包含某段中文的行」来取锚点，结果命中了内联词典的**巨型单行** `Object.assign(DICT,{…})`（这一行本身确实是唯一的，所以锚点唯一性检查通过了），整行被替换成一个短串 → 产物语法错误 + 那份追加词典被毁。靠 `.bak` 完整还原。

现在 `patches/apply.js` 有两道新哨兵：

1. **大批量删除哨兵**：`replace` 的锚点 ≥600 字符、而替换内容不足其 25% → 直接拒绝（这类事故的指纹）。
2. **语法哨兵**：写入前对 HTML 里每个内联 `<script>` 用 `new Function` 做一次**纯语法解析**（只编译不执行），产物只要语法不过就拒绝写入、原文件不动。

生成器侧同时立规：**锚点必须按「行首缩进」匹配**（`/^\s{4}"…"/`），并且要求命中行唯一 + 行长度上限，防止再次命中巨行。

# 二十二、v3.4.6：手机端三修（灵敏度 / 自动全屏横屏 / 主界面重排）+ 移除无效的「本局已赚」

## 22.1「本局已赚」为什么没用 → 直接移除

改造面板只有一个入口：主菜单的 `#btnUpg`（暂停页没有入口）。所以 `buildUpg()` 里的 `S.state==="playing"` **永远为假**，那一行永远显示 `--` —— 纯粹的占位。

对局内的本局收入本来就有更合适的位置：HUD 的「本局信用点 +N」和结算页的「本局获得」。因此把它从改造面板删掉，钱包条现在只剩「钱包」与「已投入」两项；随之无用的 `const playing=…` 一并删除。

## 22.2 触屏灵敏度：0.0021 → 0.0038 rad/CSS-px

实测旧手感：`P.yaw -= lk.dx * 0.0021` → 想转 180° 需要 **1496 CSS px**，横屏手机上接近两屏，所以"转不过身"。

| | 旧 | 新 |
|---|---|---|
| 每像素转角 | 0.0021 rad | **0.0038 rad** |
| 180° 需要 | 1496 px（≈1.8 屏） | **827 px（≈1.0 屏）** |

对齐主流手游的默认手感；滑杆范围不变（30%–300%），老玩家仍可按习惯微调，但默认档一次到位。设置项副说明同步改成写实数字 —— `滑动转视角的速度（100% ≈ 横滑一屏转 180°）`（遵守"面板显示的数字必须与写入生效的数字同源"）。**只改触屏通道，键鼠 `sens` 完全不动。**

## 22.3 自动全屏 + 锁定横屏

新增 `Mobile` 模块：

- **在用户手势内**触发（菜单任意按下 / 点「进入扇区」）→ `requestFullscreen({navigationUI:'hide'})`；
- 全屏生效后再 `screen.orientation.lock('landscape')`（未全屏时 lock 会被浏览器拒绝，故分两步）；
- 退出全屏时 `unlock()`，把方向交还系统；下一次点菜单会重新进入；
- 新增设置项 **「自动全屏横屏」`autoFull`**（默认开），关掉后不再请求；
- **平台兜底**：iOS Safari 既不支持 Fullscreen API 也不支持 orientation.lock —— 全程 try/catch 静默跳过；此时**竖屏会显示一条「建议横屏」提示条**（`#rotTip`），旋转后自动消失，且不阻塞任何点击；
- 只在 `(pointer:coarse)` 生效，请求前先看 `fullscreenElement`，已是全屏不重复请求。

## 22.4 主界面（横屏手机）重排

**实测到的问题**：`@media (max-width:820px)` 是**按宽度**的断点，而手机横屏是 **844×390**（宽度 > 820）→ 落到桌面样式：`#menu .inner{margin-left:8%;max-width:400px}`，并且**没有 max-height**。于是 `.inner` 撑到 825px 高，在 390px 视口里上下都被裁掉 —— 修改前的截图里 `NULL // SECTOR` 标题整个在屏幕外，底部说明也不可见。

**修法**：新增 `@media (pointer:coarse) and (orientation:landscape) and (max-height:600px)`：

- `#menu .inner` 改为两栏 grid：**左列** = 标题 / 副标题 / 简介 / 生涯最佳 / 成就进度 / 底部说明；**右列** = 按钮矩阵（`进入扇区` 跨 3 列，其余 3 列排布）；
- 标题字号 `clamp(20px,4.2vw,32px)` 跟随视口；另有 `max-height:400px` 的更紧凑档；
- 实测结果：整块 **810×319 落在 844×390 内**，11 个按钮**全部在视口内**，无滚动，标题完整可见。

**底部说明按设备分流**：桌面显示「桌面端 Chrome / Edge · 需要鼠标 · ESC 暂停」，触屏显示「触屏：左半屏移动 · 右半屏拖动转视角 · 右上角 II 暂停」。由 `<html class="touch">` 驱动（与 `Input.touchMode()` 同源，不是写死媒体查询），所以强制触屏调试时也一致。

## 22.5 又一处工具链加固（这次是"静默跳过"）

补丁 `once` 标记原来是我按 `NS36_` + 文件名第二段自动拼的，于是 **68/69 都是 `NS36_MOBILE`**、**70 的 `NS36_I18N` 与既有的 `NS36_I18N_DICT_ADD_TOUCH` 撞车** → 后两份补丁被判定「已应用」而**整条静默跳过**，最坑的是编排器还照样打印 `applied`（`break` 之后无条件打印）。

# 二十三、v3.4.7：自动射击 / 辅助瞄准增加视线（LOS）判定 —— 不再隔墙开枪

`aimAssist` 选目标**只用角度差**，没有任何视线判定。于是敌人躲在掩体后时：

- **「对准自动开火」照样触发** —— 准星扫过墙后敌人的位置就开枪；
- **辅助瞄准还会把准星往墙后的敌人拽**。

| 敌人在同侧无遮挡 9.05m | `aimTgt=true`，正常开火 | `aimTgt=true`，正常开火 |

## 23.2 修法：候选目标必须「看得见」

```js
  const lim=d-.25;

}
```

- **口径与既有判定完全一致**：导弹锁定的"被墙挡住不算锁定"（`findLockTarget`）和敌兵视野（`e.seen`）用的就是 `World.raycastWorldDist`。原则只有一句话：**看不见就打不到** —— 子弹本来就会被掩体挡下，所以"射线通不过"的目标本来就不该被自动射击。
- 判定放在**角度判定之内**：每帧只对通过视锥（6°/10°）的 0–2 个候选做射线，开销可忽略。
- 判定异常一律返回 `true`（不因射线失败而让玩家失去辅助瞄准）。
- 候选被掩体挡住时**继续扫描视锥内的其他敌人**，而不是直接放弃 —— 墙后站着一个、旁边站着一个时，辅助瞄准会正确吸附到可见的那个。
- 范围：辅助瞄准（吸附）与「对准自动开火」共用同一份候选，**一起修好**。
- **「触屏自动开火」(`autoFire`) 语义保持不变**：它是"代替你按住扳机"，对着墙开枪与手按扳机等价（还保留了贴墙预瞄的战术）。

## 23.3 测试

### 踩坑：悬浮敌人 + 测试摆位（值得记）

敌人是**悬浮单位**：出生 `y = baseY（默认 1.9）`，且每帧 `y = baseY + sin(t)*0.16`。测试里若把 y 压成 0，AI 下一帧就弹回，而瞄准计算假设 y=0 → **俯仰误差 ~10°，超出辅助瞄准视锥（6°/10°）** → 辅助瞄准从未启用，断言假红（误差 4°→9.65°，"越修越歪"）。

# 二十五、v3.4.9：自动开火三修（触屏打不出导弹/星爆炮 · 对准自动开火打打停停）

## 25.1 三个真实根因
1. **触屏没有导弹/蓄力炮的开火入口**：`Weapons.onMouseDown()`（导弹发射、星爆炮起蓄）只挂在桌面 `mousedown` 事件、`releaseShot()`（放出蓄力炮）只挂在桌面 `mouseup` 上；触屏开火键只设 `T.fire` 标志。而主循环的自动开火只调 `tryFire()`——它对 `launcher/missile` 第一行就 return。结果：**SW-9 锁定导弹与 HX-4 星爆炮在触屏上手动、自动都无法开火**（与自动开火无关的既有缺口，开了自动开火后更容易被发现）。
2. **「有时瞄准了也不开火」**：「对准自动开火」的判据 `aimTgt` 用固定 `3.2°` 偏轴角判定「准星压住」。近距敌人的**角半径**很大（5m 外半径 0.72 的敌人 ≈ 8.2°），准星明明压在敌人身上、只是偏离中心 5° → 判为未压住 → 不开火；敌人一浮动就打打停停。
3. 自动开火接管后没有这两把武器的节奏语义（何时射、何时放）。

## 25.2 修法
- **触屏开火键边沿接入**（主循环触屏分支）：按下边沿 → `Weapons.onMouseDown()`，松开边沿 → `isCharging() && releaseShot()`。桌面键鼠路径零改动。
- **`Weapons.autoTick(want, auto)`**（新导出，主循环每帧调用）：
  - `missile`：want 且已锁定 → 直接 `tryFireMissile()`（锁定本来就在 `update()` 里自动累积，发射后自动重锁）；未锁定静默等待，不刷 deny 提示。
  - `launcher`（星爆炮）：`auto` 渴望（来自自动开火而非物理按住）时自动起蓄、**满蓄（tier4）自动放出**；want 消失（对准自动开火丢了目标）立刻按当前档位放出，等价「松手」。
  - 物理按住开火键时 `auto=false`：蓄力节奏完全由玩家掌握，松手才放——手动手感不变。
- **`aimTgt` 改为按目标角半径判定**：`bestAng <= max(3.2°, atan2(radius, dist) + 0.6°)`——「准星压住」变成几何正确的「准星在敌人圆盘内」，近距大目标不再误判。吸附（aimAssist）逻辑不变。

## 25.3 验证
- 新增 `probe-autofire.js`（12 条，全绿）：导弹+自动开火锁定即射（3→2）；导弹手动按下边沿发射（2→1）；星爆炮自动起蓄/满蓄自放（4→3）；星爆炮手动按住 tier2 不自动放、松手即射（shots+1）；近距 5° 偏轴 aimTgt=true 且开火（修复前打不出）、远距 5° 偏轴 aimTgt=false 不开火；全程零报错。

# 二十七、v3.4.11：自动开火近距离修复 · 设置面板按设备折叠

## 27.1 「对准自动开火」近距离完全不触发
现象：手机端近距离（贴脸 ~7m 内）准星压在敌人身上也不自动开枪，中远距离一切正常。
复现：新增 `probe-aimfire-range.js`，强制触屏模式（`touchUI=1`，因为 `aimAssist()` 只在 `Input.touchMode()` 为真时被主循环调用）在 1.5–20m 逐距离实测。修复前实测：

| 距离 | 2m | 3m | 4m | 6m | 10m |
|---|---|---|---|---|---|
| aimTgt | ✗ | ✗ | ✗ | ✗ | ✓ |
| 俯仰角差 | 19.0° | 13.2° | 10.1° | 6.8° | 4.1° |

- **根因一（主因）**：候选筛选要求 `角差 < 固定锥角`（弱 6°/强 10°），而瞄准点取 `gp.y + radius`（比敌人中心高约 0.72m）。近距离时该高度差对应的俯仰角 ≈ 半径张角 `atan2(0.72, hd)`，**必然超过锥角** → 敌人进不了候选 → `P.aimTgt` 恒 false → 自动开火在约 6.9m（`0.72/tan6°`）内整体失效。判定阈值本身没错（v3.4.9 的 aimTgt 已按角半径判定），错在**候选筛选与判定口径不一致**。
- **根因二**：`losClear` 同样朝上沿射线，近距离斜向上更容易被地形/掩体误判遮挡。
- 附带澄清：桌面键鼠路径不调用 `aimAssist()`，桌面 `aimTgt` 恒 false 属正常设计。

修法（`NS36_AIMFIRE_NEAR`）：
- 瞄准点改为敌人**中心**（`gp.y`），`aimAssist` 与 `losClear` 同步——近距俯仰差归零，吸附朝本体中心（不再"吸到头顶"）。
- 候选锥角**叠加目标角半径**：`ang < coneDeg + angR`，与 aimTgt 判定（准星在圆盘内）统一口径。

验证：无敌靶下 1.5/2/3/4/6/8/10/14/20m 九个距离**全部 40/40 帧 aimTgt=true 且持续开火**（修复前 2–6m 恒 false）。

### 33.2 污染局：MOD / 开发者模式不计成就 · 收入 · 统计（`NS36_TAINTED`）

判定收敛到集成层三个纯函数（`MOD_ACTIVE` / `TAINTED` / `EARN_BLOCKED`），并**双重判定**：

- **开局快照** `S.modTainted = MOD_ACTIVE()`：本局开始时有启用中的 MOD 就锁定，**中途停用 MOD 也不洗白**；
- **实时检测**：中途启用 MOD（或中途开开发者模式）同样生效。

| 项 | 干净局 | 污染局 |
|---|---|---|
| 成就解锁 | 正常 | **不解锁**（`Ach.unlock` 守卫 = `runTainted ‖ TAINTED()`） |
| 信用点入账 | 正常 | **不入账**（`Econ.bank()` 被跳过） |
| 最高分 | 写入 | **不写** |
| 生涯（局数 / 击杀 / 作战时长） | 写入（`Best.save` + `Best.tick`） | **都不写**（漏掉 `Best.tick` 的话时长仍会累计，所以它单独也加了守卫） |
| 无尽最佳波次（`nullsector_endless_best_v1`） | 写入 | **不写**（`S.endlessWave` 仍照常显示本局成绩） |
| HUD「本局信用点」 | 按分数显示 | 显示 **+0**（不预支不可能拿到的钱） |
| 结算页 | 常规 | 「本局获得 **0 信用点 · 不计入**」、成就行加 **MOD 锁定 / DEV 锁定**、难度行加 **MOD** 标记、历史最佳行加 **本局不计入统计** |

**入账口径的细节**：
- **MOD 局一律不入账**——不给 MOD 通过配置开后门的可能；
- **开发者模式默认也不入账**（`CONFIG.ECON.devEarn` 默认 `true` → `false`）。该配置键保留，显式设成 `true` 才会恢复入账（留给 MOD 覆盖，属既有兼容约定）。

**兼容性**：已解锁的成就、既有最高分 / 生涯数据、钱包余额都不受影响；被污染的局只是「不写新数据」。`Workshop` 新增 `active()` / `activeList()`（启用且解析成功的 MOD）。

  3. 敌人可能走进「从玩家位置 BFS 不可达」的孤格（夹缝/围合内院）——此时流场帮不上忙，必须及时让位给旧式行为。

## 36. v3.4.20 —— 敌人跳跃 · 哨塔机制 · 跳跃头顶瞬移修复

### 36.1 修复：跳跃时头顶有障碍物被「瞬移」

- **根因**：玩家跳到 y>0.5 后，碰撞带 [y, y+1.8] 会够到头顶天桥的底面（2.2~2.7m）；此时玩家中心在天桥足迹内， 的「中心在箱内」分支把人推到最近的箱边 —— 宽桥就是十几米的横向瞬移。
  - 落地判定本身已有  保护，问题出在横向推挤，不在竖直吸附。
- **修法（NS36_JUMPFIX）**：新增 （头顶净空，与 groundHeightAt 同一套足迹扩大口径）；玩家上升**穿越**箱底的那一帧，把 y 钳到  并清零 vy（撞头止升，留缝防浮点推挤）。只处理「这帧才穿越」的情况：本来就在矮顶下走动的（头已超高）保持既有推挤行为。

### 36.2 敌人跳跃（NS36_JUMP）

## 37. v3.4.21 —— 修复「敌人开火但子弹消失」（弹丸销毁边界写死 ±41）

### 37.1 现象与根因

玩家反馈「部分敌人发动攻击时子弹会消失」。排查弹道全生命周期（生成 → 存活 → 命中/销毁）后定位到：

`Projectiles` 里有两处**硬编码的销毁边界 ±41**：

- `updateBallistic`（迫击弹）：`if(p.life<=0||Math.abs(gp.x)>41||Math.abs(gp.z)>41||gp.y<-.5)boom=true;`
- 普通弹分支：`else if(p.g.position.y<.05||Math.abs(p.g.position.x)>41||Math.abs(p.g.position.z)>41){...kill=true;}`

±41 是**旧版 half=39 地图**（围墙中心线 40.8）留下的余量。但 v3.4.18 起场地尺寸按图可配（half 28~56）：
VIADUCT 46 / HIVE 50 / BASTION 52 / MOD 最大 56，场地边界远在 41 之外。
于是**任何跨过 |x| 或 |z| = 41 的弹丸，都会在场地内部的半空中被销毁**——玩家看到的就是「敌人明明开火了，子弹却不见了」。

### 37.2 影响的敌人与场景

| 敌种 | 弹道类型 | 表现 |
|---|---|---|
| 哨兵 SENTINEL（homing:0） | 非制导 | 飞到 41 处凭空消失（火花） |
| 轰炸者 BOMBARDIER（射程 **70m ≫ 41**） | 迫击弹 | 在 41 处**提前空爆**，落点比玩家近几米到几十米 |
| 塔顶驻守单位（v3.4.20 全图射程 + 10s 弹寿） | 非制导 | 跨图射击打不出去 |
| 创意工坊自订敌种（homing:0 且射程远） | 非制导 | 同上 |

不受影响：狙击者 / 执行者走制导弹分支（无此边界）；爆破者为自爆。经典 6 张 half=39 的图坐标最大 ±39，恰好不会越过 41，**所以这个 bug 只在 4 张大图与 MOD 大图上出现**——这也解释了「部分敌人」「有时才发生」。

### 37.3 修法（`NS36_BOUND41`）

销毁边界改为**随当前地图计算**：

```js
function outOfField(p){ const B=World.half()+3; return Math.abs(p.x)>B||Math.abs(p.z)>B; }
```

- 取 `half+3`（地板半幅；围墙在 half+1.8±0.8，弹丸正常会先撞墙，这里只作兜底）。
- half=39 时旧值 41 → 新值 42，经典图仅多 1m 余量，**行为不变**。
- 顺带修掉同一类遗留：狙击（kite）与轰炸者（mortar）的后撤落点夹取写死 36（= half39−3），大图上永远走兜底分支；改为 `World.half()-3`，half=39 时数值完全相同。
